# ubuntu-kvm-iac-pipeline

End-to-end infrastructure automation pipeline for Ubuntu KVM: a golden image built with **Packer**, 3 VMs (1 master + 2 workers) provisioned with **Terraform** (the `dmacvicar/libvirt` provider), baseline configuration with **Ansible**, and an optional single-master **Kubernetes** cluster bootstrapped with kubeadm.

Run all commands below on an **Ubuntu host with KVM/libvirt enabled** (not on Windows/macOS).

## Architecture

| Stage | Tool | Output |
|---|---|---|
| 1. Golden image | Packer (QEMU/KVM + autoinstall) | `packer/output-qemu/ubuntu-noble-kvm.qcow2` |
| 2. VM provisioning | Terraform `dmacvicar/libvirt` | 1 master + 2 workers (cloud-init: hostname, user, SSH key) |
| 3. Baseline configuration | Ansible `site.yml` | Hardening, swap off, sysctl, container prerequisites (containerd) |
| 4. Kubernetes bootstrap | Ansible `k8s.yml` | kubeadm cluster (Flannel CNI, workers joined) |

## Quick start

```bash
make image        # 1. Packer: build the golden image (~10-20 min)
make cluster      # 2. Terraform: provision the 3 VMs
make configure    # 3. Ansible: baseline roles (auto-regenerates the inventory)
make k8s          # 4. Ansible: kubeadm init + join + Flannel
make verify       # 5. Post-deployment checks (services, kubectl get nodes)
```

`make help` lists all targets. The Ansible inventory is generated from the Terraform state (`scripts/generate-inventory.py`), so there is no manual IP copy-paste step; it is refreshed automatically whenever you run `make configure`.

## Host prerequisites

```bash
# KVM/libvirt
sudo apt install qemu-kvm libvirt-daemon-system libvirt-clients virtinst make
sudo usermod -aG libvirt,kvm "$USER"   # log out and back in

# Tooling (one way to install them)
# Packer >= 1.9    : https://developer.hashicorp.com/packer/downloads
# Terraform >= 1.5 : https://developer.hashicorp.com/terraform/downloads
# Ansible >= 2.15  : pipx install ansible-core

# SSH keypair for VM access (default path used by this pipeline)
ssh-keygen -t ed25519
```

> If the Terraform provider fails to load, also run `sudo apt install libvirt-dev`.

## Stage details

### 1. Build the golden image with Packer

```bash
cd packer && packer init . && packer build .    # or: make image
```

The image contains Ubuntu Server 24.04 (Noble), qemu-guest-agent, python3, and a temporary `packer` user (removed during the hardening stage).

### 2. Provision 3 VMs with Terraform

```bash
cd ../terraform && terraform init && terraform apply    # or: make cluster
```

Each VM gets a cloud-init disk (hostname `master-1` / `worker-1` / `worker-2`, user `ubuntu` + your SSH key, password login disabled) and a qcow2 disk backed by the golden image. VMs use the libvirt `default` network (DHCP, `192.168.122.0/24`); IP detection uses the qemu guest agent baked into the image. Override any setting via `terraform.tfvars` (see `terraform.tfvars.example`).

### 3. Baseline configuration with Ansible

`make configure` regenerates `ansible/inventory/generated.ini` from the Terraform state, then applies `site.yml`:

- **common** — apt update/upgrade, base packages, timezone (`Asia/Jakarta`, change it in `roles/common/defaults/main.yml`), hostname, qemu-guest-agent.
- **hardening** — SSH drop-in (no root login, no password auth), UFW (OpenSSH only), unattended-upgrades, removal of the `packer` builder user.
- **swap_off** — `swapoff -a` + comment out swap entries in `/etc/fstab` (Kubernetes prerequisite).
- **kernel_params** — `overlay` & `br_netfilter` modules + sysctls (`ip_forward`, `bridge-nf-call-iptables`, etc.).
- **container_prereq** — install containerd, enable `SystemdCgroup`, set the pause sandbox image.

### 4. Kubernetes bootstrap

```bash
make k8s
```

- **k8s_node** (all nodes) — adds the `pkgs.k8s.io` apt repository and installs `kubeadm`/`kubelet`/`kubectl` pinned to `k8s_version` (`roles/k8s_node/defaults/main.yml`, default `1.31.4-1.1`), then holds the packages.
- **k8s_master** — `kubeadm init` with the Flannel pod CIDR (`10.244.0.0/16`), kubeconfig for the admin user, applies the Flannel CNI manifest, and generates the worker join command.
- **k8s_worker** — joins each worker using the command registered on the master (idempotent: skips nodes that already have `/etc/kubernetes/kubelet.conf`).

### 5. Verify

```bash
make verify
```

Checks containerd/qemu-guest-agent/kubelet are active, swap is off, waits for all nodes to report `Ready`, and prints `kubectl get nodes -o wide`.

## Notes

- **Make sure SSH key access works before running the playbook** — the hardening role disables SSH password login.
- IPs are assigned via DHCP; if you ever recreate the VMs, rerun `make inventory` (or `make configure`, which does it for you). For stable leases, add MAC-based reservations to the libvirt network.
- If `kubeadm init` fails halfway, clean up with `kubeadm reset -f` on the affected node and rerun `make k8s`.
- The pod CIDR (`10.244.0.0/16`) is deliberately different from the libvirt network (`192.168.122.0/24`) to avoid routing conflicts — keep this in mind when switching CNIs.
- To upgrade Kubernetes later: change `k8s_version` in `roles/k8s_node/defaults/main.yml` and rerun `make k8s`, then `kubectl` node-by-node drains/uncordons.
- Teardown: `make destroy` (or `terraform -chdir=terraform destroy`), then `virsh vol-delete --pool k8s-lab-vms k8s-lab-vms-base.qcow2` to remove the base volume as well.
